## Назначение и структура проекта
Консольное приложение для ведения и анализа списка туристических маршрутов с сохранением в JSON:
* `main.py` — консольное меню, диалоги с пользователем и обработка ошибок ввода/вывода.
* `logic.py` — чистая бизнес-логика: валидация данных, добавление, поиск, смена статуса, удаление и статистика.
* `storage.py` — загрузка и запись JSON-файлов в кодировке UTF-8.
* `data.json` — рабочий файл с примером туристических маршрутов.
* `test_logic.py` и `test_storage.py` — автоматические тесты на базе `assert` и `TemporaryDirectory`.

## Формат данных (`data.json`)
JSON-массив объектов со следующими обязательными полями:
* `id` (`int` > 0) — уникальный номер маршрута.
* `title` (`str`) — непустое название маршрута.
* `category` (`str`) — категория местности (горы, лес, вода и т.д.).
* `amount` (`int` >= 0) — длина маршрута в целых километрах.
* `completed` (`bool`) — статус прохождения (`true` или `false`).

## Путь одной записи (от ввода до JSON и обратно)
1. Пользователь в `main.py` вводит строку названия, категорию и целое число километров.
2. Функция `add_record()` в `logic.py` очищает пробелы по краям (`.strip()`), вычисляет новый `id = max(id) + 1`, ставит `completed = False` и упаковывает всё в словарь `dict`.
3. При сохранении `save_records()` в `storage.py` проверяет типы через `validate_records()` и сериализует список словарей в текст JSON (`json.dump` с `ensure_ascii=False`), превращая `False` в `false`.
4. При следующем запуске `load_records()` читает файл через `json.load()`, преобразуя JSON-объекты обратно в словари Python, и прогоняет их через валидацию.

## Результаты проверок приёмки
Все сценарии из таблицы приёмки проверены вручную и автотестами:
* Отсутствие `data.json` корректно запускает программу с пустым списком.
* Некорректный ввод (пустые строки, отрицательные километры, буквы вместо чисел) отклоняется с повторным запросом.
* Поиск по подстроке работает без учёта регистра.
* Удаление требует строгого подтверждения словом `да`; после удаления ID оставшихся записей не сдвигаются.
* При повреждённом `data.json` программа выводит причину ошибки и завершается без перезаписи исходного файла.
